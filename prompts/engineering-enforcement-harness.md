### DEC3 — `@me-sachin-singh` is correct; the docs are wrong (decided)

`github-setup.md` and `git-workflow.md` say **`@ms-sachin-singh`** in five places.
`gh auth status` reports the real account as **`me-sachin-singh`**, which is what the committed

This matters more than a typo normally would: **an invalid CODEOWNERS file is silently ignored by

### DEC4 — reuse the versioning that already exists (decided)

`versioning.md` §3 prescribes an `APP_BUILD` `--define` and a `{version, sha, builtAt}` `version.json`.
The repo already solves the same problem a different way, and **solves it better for this app**:

- `scripts/generate-version.mjs` writes `src/app/core/version/app-version.ts` (baked into both bundles)
  and `public/version.json`, using `${shortSha}.${Date.now()}` — so a **redeploy of the same commit**
  still trips the update prompt. A bare SHA would not.
- `src/server.ts:60` already serves `GET /version.json` with `Cache-Control: no-store`.
- `src/app/shared/services/update-checker.ts` already compares running vs deployed and opens a
  non-closeable update dialog, on open / navigation / refocus / 10-min poll, throttled to 30s.

So: **no `APP_BUILD` define, no rewrite.** We add the two missing _fields_ (semver `version`, bare `sha`)
alongside the existing id, and fix the documents that describe machinery we don't have.

> **`CLAUDE.md` currently claims the `APP_BUILD` define exists. It does not.** That line gets corrected
> in Phase 6 too.

### DEC5 — the service-worker reconciliation in `versioning.md` §5 is a non-issue (decided)

`src/service-worker.ts` is 40 lines of **Netcore/FCM push config**, dynamically served at `/sw.js`.
It has no cache, no `skipWaiting`, no update flow. There is no competing "new version available" prompt

## 2. The three enforcement layers

Lifted from `github-setup.md` §0, with this repo's actual gaps filled in.

| Layer                   | Runs            | Enforces                                                                                 | Bypassable                |
| ----------------------- | --------------- | ---------------------------------------------------------------------------------------- | ------------------------- |
| **Local** — husky       | at `git commit` | format, lint, **commit message**, **branch name**                                        | yes, `--no-verify`        |
| **CI** — Actions        | every PR push   | lint, test, build, storybook, format, **PR title**, **commit messages**, **branch name** | no, once required         |
| **Platform** — rulesets | at merge        | no direct push, review required, **CI green**, squash-only, tags immutable               | only listed bypass actors |

**The platform layer is the only one that actually holds.** Local hooks are advisory by design; CI is
truth; the ruleset is what makes CI's truth binding. That ordering drives the phase order below — and it
is why Phase 3 (required status checks) is the phase that matters most.

## 7. Risks

| Risk                             | Why it bites                                                                                                                                                                        | Mitigation                                                                                                                                                                                        |
| -------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Locking yourself out**         | An Active ruleset requiring a check that never runs blocks every merge, including the fix                                                                                           | Phase 2 before Phase 3, always. Evaluate mode first. The admin bypass stays.                                                                                                                      |
| **Required check name drift**    | The ruleset matches on the **job name**.
